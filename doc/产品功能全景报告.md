# DBMS 数据库管理平台产品功能全景报告

> 基于当前代码库（前端路由、后端 API、数据模型、调度与 Agent）梳理。本文描述已落地的产品能力及其边界，不将规划能力表述为已交付能力。
>
> 更新时间：2026-08-30；产品形态：面向 DBA、运维与研发的统一数据库运维与数据操作平台。

## 1. 产品定位

DBMS 将数据库资产、日常运维、备份恢复准备、数据访问、SQL 发布、巡检诊断和外围自动化能力放在同一控制台中。当前支持的数据库类型为 **MySQL、MongoDB、Redis、PostgreSQL、Doris**；其中不同类型可使用的连接管理、会话探测、备份和数据操作能力并不完全相同，应以各模块的实际入口和校验为准。

平台采用“**集群是授权最小范围、实例是执行与采集对象**”的设计：用户先获得菜单入口，再在获授权的集群内查看、查询、变更或执行操作。管理员拥有全量权限，普通用户同时受菜单权限和集群权限限制。

## 3. 功能说明

### 3.1 运行总览与资产管理

**运行总览**是登录后的默认入口，用于汇总平台运行态信息并提供业务页面跳转。资产管理以“集群 + 实例”两层建模：集群承载业务线/命名空间、环境、数据库类型等归属；实例保存主机或域名、端口、账号与加密后的连接密码、启停状态及已解析 IP。

支持创建、编辑、删除和按数据库类型筛选实例；域名类地址既可手工刷新解析，也会由调度器周期刷新。实例可绑定 JumpServer 资产，具备权限的用户可从平台生成受控跳转链接。实例状态检测配置可调整采集轮询与状态判断相关参数。

### 3.2 资源管理

资源管理提供从申请到回收的闭环页面：

- **数据库申请**：提交数据库资源申请；
- **申请预览**：集中查看申请内容与处理前信息；
- **数据库回收**：发起或处理数据库回收；
- **申请流水**：查询申请及处理历史。

该域与资产、权限、审计结合，适合把数据库资源的创建/回收流程纳入统一留痕。具体审批流规则以当前后端实现和部署侧流程配置为准。

### 3.3 多数据库服务管理

所有类型均提供集群管理和实例管理；页面按数据库类型隔离，底层复用资产与监控框架。

| 数据库 | 当前专属能力 |
| --- | --- |
| MySQL | 实例详情、复制拓扑与状态、连接管理、会话探测；支持主从在线切换/故障切换、高可用域名配合与复制重建能力。 |
| MongoDB | 实例详情、连接管理、会话探测；覆盖 mongod/mongos、复制集状态等采集场景。 |
| Redis | 连接管理；支持单节点、主从和 Cluster 的资产与拓扑采集场景。 |
| PostgreSQL | 集群和实例管理；纳入监控、数据访问与备份策略能力。 |
| Doris | 集群和实例管理，并有 Doris 采集器支持。 |

“连接管理”面向数据库连接信息与运行连接相关管理；“会话探测”当前提供 MySQL、MongoDB 专属入口。会话探测读取与启动需要查询权限；终止会话等写操作需要变更权限，前端和后端均进行限制。

### 3.4 监控、巡检与诊断调优

平台通过数据库类型采集器和 Node Exporter 采集运行指标，监控快照按数据库类型保存并提供最新状态读取。调度侧支持并发采集、缓存预热和历史快照清理。

**巡检管理**包含巡检状态与巡检参数配置，可定期或手动执行巡检，生成告警生命周期记录并支持通知。当前连接异常检测包含：

- MySQL `Aborted_connects` 近十分钟增量；
- Redis `blocked_clients`；
- PostgreSQL 14+ `sessions_fatal` 近十分钟增量。

上述指标是巡检项而非完整的登录认证审计；单项采集失败不会阻塞其他巡检项。参数检查通过可配置的定时采集任务保存配置快照，并在“参数检查”页做比对与展示；“慢查治理”提供慢查询治理入口。

### 3.5 数据访问与操作审计

数据访问域提供四类页面：

- **数据查询**：在已授权集群中选择数据库和对象，执行受校验的查询；
- **数据变更**：执行受校验的变更/命令；支持 MySQL、MongoDB、Redis、PostgreSQL 的差异化校验与执行；
- **历史记录**：按时间、用户、数据库类型、业务线、环境、集群、结果和关键字查询操作历史；
- **权限申请**：申请数据源访问权限。

系统会选择满足条件的目标实例执行操作，并维护执行 ID 与取消回调。查询/变更的请求、目标实例、耗时、执行结果及截断后的语句会写入审计链路；配置 ClickHouse 时还可使用查询审计存储。非管理员仅能查看自身允许范围内的记录。

### 3.6 SQL 上线、AI 审核与数据复制

**SQL 上线**用于提交发布单并跟踪工单历史。发布服务包含执行、回滚备份、Agent 协作和发布前审查链路；对于 AI 审核，系统按语句流式接收模型输出，同时以“每条语句唯一且行号匹配的最终 JSON 结论”作为可发布判断，避免把模型的中间文本当作最终批准。

**AI 模型管理**支持维护 OpenAI 兼容模型配置、启用/禁用、设为默认、连通性检测和 Thinking 开关。密钥在接口和界面输出中应脱敏；模型实际可用性仍取决于部署的模型服务及网络配置。

**数据复制**提供“任务管理”和“配置中心”两个入口，用于维护复制任务及其运行配置，与调度/结果查询形成统一的自动化任务体验。

### 3.7 备份管理

备份域覆盖 MySQL、MongoDB、PostgreSQL：

- **备份总览**：按业务、数据库类型、环境、集群和结果筛选；默认聚焦生产环境，汇总统计与列表跟随同一筛选结果；
- **策略管理**：分别维护 MySQL、PostgreSQL、MongoDB 策略，配置目标实例、工具、cron、保存路径、压缩、通知和远程执行等；
- **备份记录**：查看执行状态、时间、大小、失败信息，支持下载/删除等管理动作；
- **备份配置**：管理备份工具、S3 对象存储与备份密钥；
- **Agent 管理**：登记、检测和使用跨网络/数据中心的备份 Agent；
- **通知地址管理**：维护失败通知目标，策略或集群可指定目标；未指定时使用全局/HA 回退目标。

MySQL 支持全量及 binlog 增量相关配置；MongoDB 支持全量或单库的部分备份（可排除集合）；PostgreSQL 可按数据库和表包含/排除范围备份。备份可本地执行，也可提交给远程 Agent。远程任务会被周期对账；Agent 的进程内任务状态是默认行为，启用可选恢复机制后可在特定重启场景恢复监视，不等价于容器重启后自动重跑备份。

### 3.8 调度、域名、HA 与物理机探测

**任务管理**支持 cron 表达式维护调度任务及其执行结果查询。系统内置调度还负责备份策略、巡检、监控采集、缓存预热、快照/结果清理、远程备份对账、域名刷新、参数采集与物理机探测。

**高可用配置管理**用于维护 MySQL 高可用相关配置；在主从切换场景中可配合 DNS 切换脚本和域名解析校验。

**物理机探测管理**通过 vCenter 只读连接发现虚拟机/ESXi 相关事实。配置 vCenter 和探测规则后，可手动或周期运行。手动发起采用异步运行记录：接口快速返回运行 ID，任务按匹配到的数据逐条持久化，前端轮询运行和详情以展示进行中的部分结果。地址识别优先使用管理 VMkernel，兼容 `vmk0` 和 IP 形态主机名回退；vSAN 类型保持 vSAN 标记。探测路径只做连接、查询和断开，不执行 vCenter 写操作。

**域名配置管理/阿里云域名工具**提供两层能力：平台内资产域名的解析刷新，以及经授权的阿里云域名配置和记录查询、新增、编辑、启停、删除。阿里云密钥应仅保存于受保护配置中，所有变更写入审计。

### 3.9 身份、权限、审计与开放集成

认证支持本地账号、LDAP 和基于 OAuth2/OIDC 的 SSO；登录态使用 JWT，并支持空闲超时控制。用户管理包括用户信息、角色组、用户菜单权限、数据源权限组及权限申请处理。

权限模型由三层组成：

| 层级 | 控制内容 |
| --- | --- |
| 菜单权限 | 决定是否可见并访问模块入口；角色组权限与用户直配权限合并生效。 |
| 集群权限 | 以集群为最小粒度授予 `实例查看`、`查询`、`变更`、`执行`。 |
| 数据源权限组 | 可将集群权限打包分配给用户，便于批量授权。 |

前端仅作体验层控制，后端接口会再次校验登录状态、菜单权限和集群权限。关键配置、资产、DNS、备份和数据操作写入审计日志。

开放能力包括：

- **MCP 开放平台**：提供 MCP 状态、资源与工具相关能力，供外部智能体/系统对接；
- **API Key 外部接口**：外部系统可按 API Key 获取其可变更范围内的集群、发起受范围校验的数据执行，以及请求 AI 分析；
- **JumpServer 集成**：维护连接配置、连通性检测、实例资产绑定，并支持 CSV 导入映射；
- **SSO 配置**：维护第三方身份提供商接入参数与回调链路。

## 4. 核心业务闭环

### 4.1 资产到运维闭环

`创建集群/实例 → 解析主机地址 → 采集监控快照 → 巡检并生成告警 → 查看详情/诊断 → 调整 HA、备份或配置 → 审计留痕`

### 4.2 数据访问与发布闭环

`申请集群权限 → 获授菜单与集群权限 → 查询元数据/执行查询 → 必要时提交变更或 SQL 上线 → AI 审核与执行/回滚保障 → 查询历史审计`

### 4.3 备份保障闭环

`配置工具/密钥/存储/通知与 Agent → 创建策略和范围 → cron 或手动触发 → 本地或 Agent 执行 → 对账执行状态 → 总览、记录、下载与失败通知`

## 5. 技术与数据架构

| 层次 | 当前实现 |
| --- | --- |
| 前端 | Vue 3、Vue Router、Element Plus、ECharts、CodeMirror；以页面路由和菜单权限渲染控制台。 |
| 服务端 | Flask REST API、SQLAlchemy、Flask-JWT-Extended、APScheduler。 |
| 元数据 | 默认可使用 SQLite；生产建议 MySQL。保存用户、权限、资产、策略、快照、巡检、任务、审计等。 |
| 目标采集/执行 | 后端通过各数据库驱动与工具直连；支持 MySQL、MongoDB、Redis、PostgreSQL、Doris 采集器及 Node Exporter。 |
| 缓存与审计扩展 | Redis 用于缓存/预热；可选 ClickHouse 承载查询审计事件。 |
| 远程执行 | 可选 dbms-agent，以 HTTP 接收备份/发布执行任务；镜像包含常用 dump 工具。 |
| 外部集成 | LDAP、OAuth2/OIDC、S3、企业微信/邮件、阿里云 DNS、JumpServer、MCP、OpenAI 兼容模型服务。 |

敏感连接信息以 Fernet 加密保存；生产环境必须显式设置 `SECRET_KEY`、`JWT_SECRET_KEY`、`FERNET_KEY`，并使用 HTTPS、LDAPS/TLS、最小化数据库账号权限和受限的备份目录权限。

| 角色 | 建议授权范围 |
| --- | --- |
| 平台管理员 | 用户与角色、全量资产、全局配置、外部集成、备份基础设施。 |
| DBA/运维 | 指定集群的实例查看、查询、变更/执行；巡检、诊断、备份和 HA 的相应菜单。 |

## 7. 当前边界与上线注意事项

1. 数据库类型的“资产与采集支持”不等于全部具备同等的会话、备份、发布或 HA 能力；前端专属入口和后端校验是最终边界。
2. PostgreSQL `sessions_fatal` 依赖 PG14+，且只反映该项统计，并非完整认证失败日志。
3. 物理机探测的异步与增量落库已实现；真实 vCenter 环境的性能和兼容性仍应在目标环境验收。
4. AI 连通性检测验证的是当前模型服务配置可否调用；模型判断仅作为审核环节的一部分，发布的最终风险控制仍应保留规则、权限和人工责任。
5. 远程 Agent 默认使用进程内任务状态。若以多 Worker 方式部署，需要会话黏性或共享任务存储；重启恢复需按 Agent 文档显式启用并使用持久化任务目录。
6. 查询审计写入 ClickHouse、对象存储下载、通知、阿里云 DNS、SSO、JumpServer 等均依赖部署侧网络、账号和密钥配置，应在生产上线清单中分别验收。

## 8. 建议的验收清单

- 为每种数据库类型建立一套最小测试资产，验证录入、采集、展示、删除及权限隔离。
- 用普通用户验证“无菜单不可访问、无集群权限不可查看/查询/变更、仅查询不可 Kill”。
- 为每一种备份策略完成一次手动备份、一次调度备份、一次失败通知、一次文件下载验证。
- 验证 SQL 上线的审批/AI 输出、失败回滚备份和历史留痕。
- 分别演练 LDAP/SSO、API Key、MCP、JumpServer、S3、阿里云 DNS 等已启用集成的失败降级和审计。
- 在真实网络下压测监控采集、巡检、远程 Agent 与 vCenter 探测，确定并发数、超时和任务周期。
